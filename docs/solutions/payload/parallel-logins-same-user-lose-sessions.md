# Параллельные входы одного пользователя теряют сессии

## Симптом

Локальный CI: 2 из 54 e2e падали нестабильно. Вход проходил (редирект на `/me`), а дальше страница вела себя как для гостя: нет поля комментария, заявка на усыновление не отправляется. Падали разные спеки, но все входили как `citizen@test.local`.

## Причина

В Payload 3 (`auth.useSessions`, по умолчанию включено) сессии хранятся массивом `sessions` в документе пользователя. `addSessionToUser` (`payload/dist/auth/sessions.js`) читает пользователя, дописывает сессию в массив и записывает массив целиком. Два одновременных входа — классический lost update: второй перезаписывает массив без сессии первого. JWT первого содержит `sid`, которого в БД больше нет → запросы идут как от гостя.

## Решение

Свой тестовый пользователь на каждый спек со входом: список `TEST_CITIZENS` в `web/scripts/seed.ts`. Новый спек со входом — добавить email в список, не переиспользовать чужой.

На проде то же самое возможно, если человек входит одновременно с двух устройств (миллисекунды) — риск принят, не чиним.

## Проверка

`npm run ci:local` — 54/54 два прогона подряд.
