# Слияние PR при параллельных сессиях: фиксировать проверенный коммит

## Контекст

PR №1 (сид реальных организаций) был проверен на коммите `a22bd52`: ревью diff, полный `ci:local`, пробный посев. Пока шёл CI, другая сессия дописала в ту же ветку коммит `e3418ef` (организаций стало 63 вместо 39). `gh pr merge 1 --rebase` слил оба — в main и на прод ушёл коммит, который никто не читал и не тестировал. Он оказался безобидным (только файл данных), CI на слитом main прогнали задним числом.

## Суть

1. **Сливать по SHA.** `gh pr merge N --rebase --match-head-commit <полный sha>`: если голова PR сдвинулась, слияние откажет. Перед этим сверить `gh pr view N --json headRefOid,commits`.
2. **`ci:local` — общий ресурс.** Скрипт пересоздаёт базы `pet_ci_local` и `pet_migrate_check` (`DROP DATABASE ... WITH (FORCE)`) и занимает порт 3199. Два одновременных запуска из разных рабочих копий ломают друг друга. Перед запуском предупредить соседнюю сессию; для точечной проверки взять свою базу и порт (`DATABASE_URL=.../pet_<имя>`, `E2E_PORT=3198`).
3. **Делить файлы до начала работы.** Соседняя сессия видна по `.claude/worktrees/` и по свежим веткам на GitHub. Договориться, кто какие файлы меняет и кто ведёт `docs/СОСТОЯНИЕ_ПРОЕКТА.md` и `docs/ПЛАН_ИЗМЕНЕНИЙ.md`.
4. **Сид, пропускающий существующие записи, запускать последним.** `seed:orgs` ищет организацию по имени и не обновляет найденную. Если формат записи ещё меняется в соседней ветке (новые поля, разбор телефонов), посев на прод ждёт её слияния — иначе старые данные останутся навсегда.

## Почему это важно

Main деплоится автоматически: непроверенный коммит в PR сразу оказывается на проде. Ревью и зелёный CI относятся к конкретному коммиту, а не к номеру PR.

## Когда применять

- Любое слияние PR, если между проверкой и слиянием прошло больше пары минут.
- Любой запуск `ci:local`, когда в `.claude/worktrees/` есть чужая активная копия.

## Примеры

```bash
FULL=$(git rev-parse HEAD)                       # коммит, на котором прошёл ci:local
gh pr view 2 --json headRefOid --jq .headRefOid  # должен совпасть
gh pr merge 2 --rebase --match-head-commit "$FULL"
```
