## 5. Текущая задача

- **Цель:** И-25 — вход через Telegram и magic-link создаёт рабочую сессию Payload.
- **Причины (найдены по коду Payload 3.90):** (1) `lib/auth/session.ts` подписывает JWT сырым `PAYLOAD_SECRET` (Payload проверяет `sha256(secret).hex[0:32]`), без заголовка `authVersion` и без `sid`/записи в `users.sessions`; (2) `Users.auth.verify = true`, а пользователь из Telegram создаётся с `_verified=false` → стратегия JWT отдаёт `user=null` даже с верным токеном (плюс Payload шлёт письмо подтверждения на `tg-…@telegram.local`).
- **Входит:** выпуск сессии через функции Payload (`addSessionToUser`, `getFieldsToSign`, `jwtSign`, `payload.secret`); TG-пользователь создаётся подтверждённым и без письма подтверждения; вход по magic-link помечает почту подтверждённой; e2e на оба входа; `TELEGRAM_BOT_TOKEN` для тестов в CI.
- **Не входит:** И-26 (форма `/verify-email`), welcome-письмо на `@telegram.local`, реальный бот-токен и домен для виджета Telegram.
- **Готово, когда:** e2e: вход через Telegram (подписанные виджетом данные) и по magic-link ведёт в кабинет, шапка показывает «Кабинет»; `npm run ci:local` зелёный.

- **Отчёт (11.11.2026): готово локально, закоммичено в main, НЕ запушено** (push = деплой — после ОК владельца).
  - Изменено: `lib/auth/session.ts` — сессия функциями Payload; TG-пользователь создаётся подтверждённым без письма, старые неподтверждённые подтверждаются при входе; magic-link: письмо ведёт на `/login/magic`, токен тратит только POST (Chrome из-за `Critical-CH` от `withPayload` и почтовые сканеры повторяют GET), переход подтверждает почту; `TELEGRAM_BOT_TOKEN` (тестовый) в `ci-local.sh` и GitHub CI; попутно И-28 (таймаут unit-тестов 15 с).
  - Проверено: новый e2e сначала падал на старом коде (оба входа), после фикса зелёный; в БД у TG-пользователя `_verified=true` и одна сессия; `npm run ci:local` — 369 unit, 72 e2e.
  - Не проверено: настоящий виджет Telegram (нет бот-токена и домена в BotFather на проде); реальное письмо magic-link (нет Resend).
  - Риски: старые cookie от TG/magic-link и так не работали — терять нечего; welcome-письмо уйдёт на `tg-…@telegram.local`, когда появится Resend (адрес не существует — отскок).
